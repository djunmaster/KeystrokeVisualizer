## Critical Issues to Fix

### High Priority

1. **Tray toggle does not broadcast CONFIG_CHANGED**
   - Location: `src/main/TrayManager.ts:55-68`
   - Problem: TrayManager toggles ConfigStore directly but never sends CONFIG_CHANGED to windows
   - Effect: Settings UI and overlay won't update when using tray menu

2. **Drag-save does not broadcast config changes**
   - Location: `src/main/ipc-handlers.ts:38-45`
   - Problem: UPDATE_POSITION only saves to ConfigStore, doesn't broadcast
   - Effect: Settings window won't reflect new position after dragging

3. **Position preset changes don't move overlay window**
   - Location: `src/main/ipc-handlers.ts:18-33`
   - Problem: UPDATE_CONFIG doesn't apply position changes to the overlay window
   - Effect: Changing position in Settings updates config but overlay stays in place

### Low Priority

4. **Multi-monitor preset calculation mismatch**
   - Location: `src/renderer/settings/components/PositionSetting.tsx:23-59`
   - Problem: Uses `window.screen` instead of Electron's `screen.getPrimaryDisplay()`
   - Effect: May place overlay unexpectedly in multi-display setups

## Recommended Fix Strategy

**Centralize config broadcasting:**

1. All config mutations should go through a single path that broadcasts CONFIG_CHANGED
2. Options:
   - A) Have ConfigStore emit events that TrayManager/ipc-handlers subscribe to
   - B) Always use IPC handlers for config changes (even from TrayManager)
   - C) Create a dedicated `broadcastConfigChange()` helper function

**For position changes:**

1. When UPDATE_CONFIG receives a position change, call `windowManager.updateOverlayPosition(x, y)`
2. For UPDATE_POSITION, broadcast CONFIG_CHANGED after saving

## Learnings

### What Worked

- **Fallback icon generation**: Creating simple colored PNG icons programmatically works well when icon files are missing
- **Disabling code signing**: `signAndEditExecutable: false` bypasses Windows symlink permission issues
- **Separate tray-icons directory**: Keeps electron-builder from trying to convert small tray icons

### What Failed

- **Initial icon generation**: Our custom PNG generator caused app-builder to crash; needed to separate tray icons from app icons
- **buildResources in resources/**: Caused conflicts with tray icon files

### Key Decisions

1. **Use actual {x,y} for presets instead of preset names**
   - Simpler: No ConfigState type changes needed
   - Trade-off: Preset detection is approximate (tolerance-based)

2. **English-only UI**
   - Avoids encoding issues across different systems
   - Consistent with code comments

3. **Default Electron icon for now**
   - Custom app icons require proper .ico/.icns generation
   - Can be added later with proper tooling
